# 작업: ETF 원장 단일화 — 합집합 + 3년 커버리지 필터

## 배경
ETF 목록이 두 벌이다. `db/seeds/04_etf_master.csv`(71행, M1이 종목을 고르는 원장)와
`data/universe.csv`(60행, 백테스트 가격 대상). 겹치는 종목은 24개뿐이다.
`Claude outputs/M2_답변_2026-09-20.md` 2절의 제안을 반영한다:
두 목록의 합집합에 3년 커버리지 95% 필터를 적용하고, 그 결과로 원장을 확정한다.

## 원칙
- 코드는 최소로. 새 파일은 `scripts/merge_universe.py` 하나(150줄 이내).
  기존 코드는 `scripts/fetch_prices.py`에 `--universe` 인자 하나만 추가한다.
- 매핑 표·검증 로직을 새로 만들지 않는다. `scripts/load_etf_master.py`의
  `SECTOR_GROUP_MAP`·`COUNTRY_GROUP_MAP`·`check_g1_leveraged_consistency`를 import한다.
  (2026-09-27 결정: `SECTOR_GROUP_MAP`에 빠져 있던 `금융`·`인터넷과플랫폼` 두 줄을
  `03_asset_groups.sql` 라벨 그대로 추가했다. 새 표를 만든 것이 아니다.)
- 스키마·`db/init`·SQL 시드·확정 수치(프리셋·그룹캡·하드캡)는 건드리지 않는다.
- `build_universe.py`는 실행하지 않는다(`universe.csv`를 덮어쓴다).
- 모르는 값은 비운다. 추정해서 채우지 않는다.
- 명령은 전부 `docker compose exec api ...`로 실행한다.
- 단계마다 보고하고 멈춘다. 다음 단계는 내가 지시한다.

## 확정된 규칙
- **정본**: `db/seeds/04_etf_master.csv`. `data/universe.csv`는 원장의 파생본이다
  (활성 종목만, 헤더는 지금 그대로 유지). 두 러너가 읽는 칸은
  `name`·`risk_tag`·`asset_group`·`sector_group`·`country_group`이다.
  `risk_tag_method`는 `product (04_etf_master.csv)`로 채우고,
  `ann_vol`·`marcap_eok`·`first_date`는 기존 값이 있으면 옮기고 없으면 비운다.
- **커버리지**: 구간 2023-01-02 ~ 2025-12-31.
  비율 = (그 종목의 구간 내 가격 행 수) ÷ (같은 구간 069500의 행 수).
  0.95 이상이면 통과.
- **상장폐지 3종목**(248260·098560·301410): 판정·가격 수집에서 빼고, 원장에는
  `active=false`로 그대로 둔다. `universe.csv`에는 넣지 않는다.
- **레버리지·인버스**: 커버리지를 통과하면 남긴다(실패 장면 1에 필요하다).
- **겹치는 24종목**: 원장 값을 유지한다. `universe.csv`와 다른 칸은 검토 파일에 표시만 한다.
- **새 종목**(`universe.csv`에만 있던 36개): 세 축은 `universe.csv`의 group_id를
  load_etf_master 매핑의 역변환으로 한글 라벨로 바꿔 넣는다. `group_id` = asset_group,
  `is_leveraged=false`(`universe.csv`는 레버리지를 제외하고 뽑았다), `active=true`,
  `risk_tag`는 **빈칸** — 사람이 채운다.

## 1단계 — 현황 확인 (코드 수정 없음)
두 CSV를 읽어 원장 71(활성 68)·유니버스 60·교집합 24·합집합 107을 확인하고 보고한다.
숫자가 다르면 멈춘다.

## 2단계 — 후보 가격 받기와 검토 파일
1. `fetch_prices.py`에 `--universe PATH` 인자를 추가한다(기본값은 지금과 같다).
2. `merge_universe.py review`:
   - 합집합에서 상장폐지 3종목을 뺀 104종목을 `Claude outputs/etf_union_candidates.csv`(ticker, name)로 쓴다.
3. `fetch_prices.py --universe "/repo/Claude outputs/etf_union_candidates.csv"`를 실행한다.
   실패 종목이 있으면 prices.csv를 쓰지 않는 기존 동작 그대로 두고, 그 목록을 보고하고 멈춘다.
4. `merge_universe.py review`를 다시 실행해 `Claude outputs/etf_merge_review.csv`를 쓴다.
   칸: ticker, name, source(both|master|universe), coverage, pass, risk_tag,
   is_leveraged, 세 축, axis_diff(겹치는 종목에서 두 목록 값이 다른 칸).
5. 보고: 탈락 종목과 커버리지, 통과한 새 종목 수, axis_diff가 있는 종목 수. 멈춘다.

## 3단계 — 사람이 risk_tag 채우기 (에이전트는 대기)
검토 파일의 빈 risk_tag를 사람이 채운다. 기준은 M2_답변 1절이다.
G1 레버리지·인버스 / G2 단일 섹터·테마·해외 섹터·원자재 / G3 시장대표 지수 /
G4 혼합·초장기 국채 / G5 중장기 국공채·회사채 / G6 단기금리·MMF.

## 4단계 — 확정과 적재
1. `merge_universe.py apply`:
   - 통과 행 + 상장폐지 3행으로 `04_etf_master.csv`를 쓴다. 기존 칸 순서와 BOM을 유지한다.
   - 활성 통과 행으로 `data/universe.csv`를 쓴다.
   - risk_tag 빈칸이 있거나 `check_g1_leveraged_consistency`가 실패하면 파일을 쓰지 않고 멈춘다.
2. `fetch_prices.py`(기본 경로)로 prices.csv를 확정 종목 기준으로 다시 받는다.
3. `load_etf_master.py`, `ingest_prices.py`를 실행한다.
   가격 표에서 빠진 종목의 행은 지우지 않고, 남은 행 수만 보고한다.
4. 검증:
   - pytest(`CLAUDE.md`의 마커 제외판)
   - ruff(app·scripts)
   - `check_asof_guard.py`
   - `price_daily` 종목 중 `etf_master`에 없는 종목 수(0이어야 한다)
   - 파이썬·TS 백테스트 러너 재실행과 `pytest -m requires_backtest`
     risk_tag가 변동성 기준에서 상품 기준으로 바뀌므로 결과는 달라질 수 있다. 차이만 보고한다.
