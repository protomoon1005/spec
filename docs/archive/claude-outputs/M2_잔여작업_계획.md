## 2단계 · 비중 산출 체인 (2~3일)

RiskSizer → WeightMapper → GroupCapEnforcer → OrderBuilder. **M4가 기다리고 있는 부분**이다.

**알고리즘은 이미 다 적혀 있다.** 상세설계서 1.5.2의 6단계를 그대로 옮기면 된다.

```
입력  s_i  통합 신호, -1 에서 +1
      lo_i = weight_min_i
      hi_i = min(weight_max_i, risk_cap_i)
      target = 1 − cash

1) 매핑     w_i = lo_i + (s_i + 1) / 2 × (hi_i − lo_i)
2) 정규화   w_i = w_i × target / Σ w
3) 클램프   w_i = min(max(w_i, lo_i), hi_i)
4) 반복     2와 3을 최대 3회, 변화 없으면 조기 종료
5) 그룹캡   상위 자산군 먼저, 하위 섹터·국가 나중. 초과분을 묶음 내부에서 비례 축소
6) 잔여     1 − Σ w 를 현금으로
```

**순서가 중요하다** — RiskSizer가 WeightMapper보다 먼저 돈다. 한도를 넘는 결정이 나온 뒤 거부하는 게 아니라, 애초에 나올 수 없게 만드는 구조다(1.4). 이 순서를 바꾸면 재시도 루프가 생긴다.

## 3단계 · Validator 4단 + 범위 자동 보정 (2일)

재원이 Spec 생성기를 완성하면 바로 이걸 통과해야 한다.

| 단계 | 내용 | FN |
|---|---|---|
| 1 스키마 | Pydantic 검증, 정의되지 않은 필드 거부 | FN-301 |
| 2 참조 | 블록 ID 실재, ETF 상장 상태, 백테스트 기간 내 가격 존재 | FN-302 |
| 3 논리 | weight_min ≤ weight_max, 허용범위 포함, 낙폭 목표와 변동성 양립성 | FN-303 |
| 4 하드캡 | 초과 값을 하드캡으로 치환하고 기록 | FN-305 |

**범위 자동 보정(FN-304)이 핵심이다.** 되묻기도 재생성도 없이 코드가 조용히 고친다.

```
[불변식]  Σ weight_min  ≤  1 − cash_min  ≤  Σ weight_max

case A. Σ weight_min > 1 − cash_min
    scale = (1 − cash_min) / Σ weight_min 을 모든 weight_min 에 곱한다
    allowed_min 미만으로는 내리지 않고, 그래도 초과하면 유니버스 축소를 요청한다

case B. Σ weight_max < 1 − cash_min
    deficit 만큼 allowed_max 와 하드캡 여유분에 비례해 weight_max 를 확대한다
    그래도 부족하면 cash 목표를 올려 잔여를 흡수한다
```

보정 내역은 `validation_logs.adjusted_bounds` 에 기록하고 사용자 화면에 그대로 노출한다.
보정 전 원본은 `SPEC_UNIVERSE.weight_min_raw` · `weight_max_raw` 에 보존한다(스키마에 이미 있음).

**기대효과 검증 항목** — "무작위 범위 조합을 대량 생성해 보정 후 실행가능성 100%, 재시도 0회". 이걸 그대로 속성 테스트로 만들면 발표 자료가 된다.

```
4단 Validator 와 범위 자동 보정을 구현해라. FN-301~306 이다.

범위 자동 보정(FN-304)의 규칙은 상세설계서 1.5.1 그대로다. 내가 아래에 붙여넣는다.
[위 불변식과 case A/B 붙여넣기]

범위 실행가능성은 재생성 대상이 아니라 자동 보정 대상이다. 절대 LLM 에 되묻지 마라.

테스트는 무작위 범위 조합 1000건을 생성해서 다음을 단언해라.
- 보정 후 불변식이 항상 성립한다
- 재시도가 0회다
- 보정 내역이 validation_logs.adjusted_bounds 에 남는다
- 원본값이 weight_min_raw / weight_max_raw 에 보존된다
```
