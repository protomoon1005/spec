### 종목 데이터

> 2026-09-20 합병으로 **국가 칸 부재와 위험등급 쏠림이 해소됐다.** 아래는 남은 것만.

- **성향 1(안정투자형)이 담을 수 있는 주식형이 하나도 없음**
  - 71종목 중 G4~G6 이 12개뿐이고 전부 채권이다
  - 등급 문제가 아니라 **원장에 저위험 주식형이 없어서**다 — 배당·커버드콜 같은 게 빠져 있다
  - 원장을 늘릴 때 그 구간을 의도적으로 채워야 한다

- **성향 3·4·5 의 선택지가 똑같음 (54종목)**
  - G1 14개가 성향 5 에서만 열리는데 전부 레버리지라 하드캡이 먼저 막는다
  - 성향을 올려도 담을 수 있는 게 안 늘어난다는 뜻 — 데모에서 성향 차이를 보이기 어렵다
  - 레버리지가 아닌 G1 종목을 원장에 넣으면 해소된다

- **종목의 순자산 칸이 없어 "대표적인 종목부터" 고를 수 없음**
  - 후보를 보충할 때 순자산 큰 것부터 넣고 싶은데 표에 칸이 없다
  - 지금은 종목코드 순이라 사실상 임의 순서다. 결과는 항상 같으므로 재현성은 지켜짐

- **옛 `sector`·`group_id` 컬럼이 남아 있음**
  - 마이그레이션이 `asset_group_id`·`sector_group_id`·`country_group_id` 세 축을 새로 만들었고,
    옛 두 컬럼은 "당분간 남긴다"로 두었다
  - `sector` 에는 한글 라벨(`반도체`)이, `sector_group_id` 에는 묶음 이름이 들어 있다.
    **둘을 섞어 읽으면 조용히 아무것도 안 걸린다** — 실제로 M1 코드가 한 번 그렇게 깨졌다
  - 읽는 쪽은 세 축만 본다(`app/repositories/etf_master.py`). 옛 컬럼은 언젠가 정리 대상

- **자산군을 배정하지 않으면 새로 상장한 ETF 를 자동으로 못 넣음**
  - 자산군이 필수값인데 그 배정은 사람이 하는 일이라서
  - 적재기가 그런 행을 건너뛴다 — 지금은 71행 전부 채워져 있어 해당 없음

- **수집 스크립트의 저장 위치를 확인할 것**
  - 예전에는 스크립트가 저장소 루트 `data/` 에 쓰는데 백테스트는 `frontend/data/` 를 읽었다
  - 합병으로 `data/` 가 들어왔다. 어느 쪽을 읽는지 한 번 맞춰 볼 값어치가 있다

### 전략서와 승인

- **승인한 전략서의 상태를 바꿀 수 없음**
  - 승인 뒤에는 고치지 못하게 데이터베이스가 막아 놨음
  - 그 잠금이 "상태" 칸까지 얼려서 `승인 → 운용중 → 종료` 로 넘어가는 것 자체가 안 됨
  - 얼려야 할 건 종목과 비중이지 상태는 아닐 가능성이 크지만, **팀 확정 전이라 코드를 안 바꿈**

- **가입으로는 일반 사용자만 만들어짐**
  - `POST /auth/signup` 은 권한을 항상 `retail` 로 고정함. 요청으로 고를 수 없음
  - `pro`·`admin` 으로 올리는 경로가 없어서 데이터베이스에 직접 넣어야 함
  - 이메일 인증도 없음. 메일 발송 경로가 없고 모의투자라 프로토타입 기준으로 생략함

- **501 로 비어 있는 API 들의 응답 형식은 바뀔 수 있음**
  - 지금은 표의 확정 칸만으로 모양을 보여주는 최소한
  - 페이징·부분 수정·오류 형식 같은 건 각자 만들 때 정함
  - **전략서(Spec) 형식만은 예외.** 전원 합의가 필요한 고정 계약

### 뉴스와 AI 모델

- **뉴스 수집 파이프라인이 제거됐는데 표는 남아 있음**
  - 2026-09-19 `jun` 이 지움 (커밋 `ee08952`, 11개 파일 1,178줄)
  - `news_articles`·`news_sentiment` 표와 벡터 색인은 스키마에 그대로 있다
  - **감성 관점의 입력이 통째로 없는 상태.** 다시 만들 계획인지 확인 필요
  - 그동안 쌓인 기사도 같이 사라졌을 수 있다 — 지나간 날은 다시 못 받는다

- **뉴스 표에 원문을 담는 칸이 있지만 채우면 안 됨**
  - 상위 규칙이 "뉴스 원문은 저장하지 않는다, 메타정보·점수·태그만 저장한다"고 못 박음
  - 다시 만들 때 이 규칙을 지켜야 함

- **문장을 숫자로 바꾼 값의 크기를 768로 정해 둠**
  - 원래 설계 문서에 크기가 안 적혀 있었는데, 크기가 없으면 검색 색인을 만들 수 없어서 정함
  - **나중에 바꾸려면 칸 타입 변경 + 색인 재생성이라 되돌리는 비용이 큼.** 쓸 모델을 빨리 정할수록 좋음

- **GPU 쪽 AI 서버는 한 번도 안 돌려 봄**
  - 코드만 있고 실행한 적 없음. GPU 있는 팀원이 처음 검증해야 함
  - GPU 없는 쪽(Ollama)은 실제로 응답을 받아 확인함
