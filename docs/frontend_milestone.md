# 프론트엔드 흐름 화면 — 마일스톤

- 작성 2026-09-25
- 현재 시스템 흐름(가입 → 로그인 → 성향 → 전략 만들기 → 하드캡 → 백테스트 → 최종 확인 → 관점 판단)을 화면으로 따라갈 수 있게 만드는 것까지
- 흐름 설명은 docs/human_manual.md, M1 기능 정의는 docs/m1_milestone.md

---

## 목표

- 사용자가 Swagger 없이 브라우저만으로 가입부터 전략서 생성까지 끝낼 수 있다
- 아직 없는 단계(하드캡, 백테스트 API, 승인, 관점 판단)는 빈 화면이라도 흐름 안에 자리를 잡아 둔다
- 화면 하나가 기능 하나다. 한 화면에 두 기능을 섞지 않는다

## 원칙

- 디자인 요소를 넣지 않는다. 디자인은 나중에 따로 한다
  - 기본 HTML 요소만 쓴다 — 제목, 문단, 입력창, 버튼, 목록, 링크
  - 색, 여백 조정, 애니메이션, 차트 꾸밈, 아이콘, 라이브러리 컴포넌트를 쓰지 않는다
  - 새 의존성을 추가하지 않는다 (TanStack Query, shadcn/ui 도 이번엔 붙이지 않는다)
- 의도 파악이 최우선이다
  - 각 화면 맨 위에 "이 화면에서 하는 일" 한 줄을 적는다
  - 서버가 돌려준 값과 오류 메시지를 가공 없이 그대로 보여 준다
  - 다음 화면으로 가는 버튼 하나를 둔다
- 백엔드 변경은 확정 결정 1번(내 계정 보기 주소) 하나뿐이다

---

## 백엔드에서 확인한 사실 (화면이 기대는 것)

- 가입과 로그인은 username 하나뿐이고 비밀번호가 없다
  - 가입: 성공하면 토큰 두 개(access, refresh)를 바로 준다. 같은 이름이면 409
  - 로그인: username 만 주면 토큰을 준다. 없는 이름이면 401
  - docs/human_manual.md 2.1 과 README 의 "이메일과 비밀번호" 서술은 낡았다
- 토큰이 맞는지만 확인해 주는 주소는 없다
- 설문: 문항 받기 → 답 보내기 → 성향 확정 → 내 성향 보기, 네 주소 모두 동작
- 전략 만들기: 요청하면 작업 번호를 준다. 결과는 진행 상황 스트림으로 온다
  - 스트림은 인증 헤더가 필요하다. 브라우저 기본 EventSource 는 헤더를 못 실으므로 fetch 로 스트림을 읽어야 한다
  - 결과는 completed(spec_id, 종목 수) / need_answer(session_id, 질문, 선택지) / failed(이유)
  - 한 번에 2분 이상 걸린다
- 전략서 내용 보기는 501 이다. 완료 후 spec_id 외에 보여 줄 게 없다
- 백테스트 실행, 결과 보기는 501 이다. 기존 /report 화면은 저장된 결과 파일을 읽는다
- 승인(최종 확인)은 501 이다
- 관점 판단 결과를 주는 주소는 없다
- CORS 는 localhost:3000 이 허용돼 있고, 브라우저용 API 주소는 NEXT_PUBLIC_API_BASE_URL 에 있다

## 확정 결정 (2026-09-25)

### 1. 로그인 화면의 토큰 인증 — 내 계정 보기 주소 추가

- 백엔드에 토큰 주인의 username 을 돌려주는 주소를 하나 추가한다
- 로그인 화면은 그 주소를 입력한 토큰으로 부르고, 돌아온 username 이 입력한 아이디와 같은지 비교한다
- 스키마 변경 없음. 이번 작업의 유일한 백엔드 변경

### 2. 전략 완료 화면 — 번호와 종목 수만, 나머지는 빈칸

- 이번에는 전략서 번호(spec_id)와 종목 수만 보여 준다
- 전략서 내용 전체(종목, 비중 범위, 리밸런싱, 신호 규칙) 자리는 칸만 두고 "추후 구현 예정" 문구로 비워 둔다
- 전략서 보기 주소(현재 501)는 이후 별도 작업으로 구현해 빈칸을 채운다

### 3. 백테스트 화면 — 기존 저장된 결과 파일

- 이미 저장된 결과 파일을 숫자 목록으로 보여 준다
- 방금 만든 전략서와 무관한 결과라는 문구를 화면에 적는다

### 4. 기존 /report 화면 — 그대로 두고 링크만

- /report 는 M4(하늘) 담당의 디자인된 화면이라 손대지 않는다
- 새 백테스트 화면에서 링크로 연결한다

## 화면 목록과 순서

1. 시작 — 로그인 여부에 따라 로그인 또는 이어서 할 단계로 보낸다
2. 회원가입
3. 로그인
4. 성향 설문
5. 성향 결과
6. 전략 요청
7. 전략 진행 상황
8. 되묻기
9. 전략 완료
10. 하드캡 (구현 예정 안내)
11. 백테스트
12. 최종 확인
13. 관점 판단

- 각 화면은 별도 주소를 가진다 (예: /signup, /login, /survey, /profile, /compile, /compile/progress, /compile/answer, /compile/done, /hardcap, /backtest, /confirm, /views)
- 로그인이 필요한 화면에 토큰 없이 들어오면 로그인 화면으로 보낸다

---

## 0단계 — 공통 바닥

- 하는 일
  - API 호출 도우미 한 개 — 주소, 토큰 헤더, 오류 메시지 꺼내기
  - 토큰 보관 — 브라우저 저장소에 access, refresh, username 을 둔다
  - 로그인 확인 — 토큰이 없으면 로그인 화면으로 보낸다
  - 진행 상황 스트림 읽기 — fetch 로 스트림을 받아 status, complete, timeout 이벤트를 나눈다
- 재사용할 것
  - API 주소는 NEXT_PUBLIC_API_BASE_URL
  - 기존 ScaffoldShell 은 흰 배경과 글자색만 지정한 껍데기라 그대로 써도 된다
- 완료 기준
  - 토큰 없이 보호 화면에 들어가면 로그인 화면으로 간다
  - 서버 오류(401, 409, 422, 501)가 화면에 그대로 찍힌다

## 1단계 — 회원가입 화면

- 하는 일
  - 아이디 입력창 한 개 (형식 제한 없음)
  - 중복확인 버튼 — 실제로는 가입 요청을 보낸다
    - 409 면 "이미 있는 아이디" 표시, 입력창 유지
    - 성공이면 가입이 끝난 것이므로 토큰을 받는다
  - 받은 access 토큰 표시와 복사 버튼
  - 가입 완료 문구와 "로그인으로 돌아가기" 버튼
- 주의
  - 중복확인과 가입이 한 번의 요청이다. 확인만 하고 가입은 안 하는 동작은 서버에 없다. 버튼 옆에 "확인되면 바로 가입됩니다" 를 적는다
- 완료 기준
  - 새 아이디로 누르면 토큰이 보이고 복사된다
  - 같은 아이디로 다시 누르면 중복 문구가 뜬다
  - 돌아가기를 누르면 로그인 화면으로 간다

## 2단계 — 로그인 화면

- 하는 일
  - 아이디 입력창
  - 토큰 입력창과 인증 버튼 — 내 계정 보기 주소를 입력한 토큰으로 불러, 돌아온 username 이 입력한 아이디와 같은지 비교하고 결과(통과/실패 사유)를 표시
  - 로그인 버튼 — 인증이 통과해야 눌린다. 누르면 토큰을 보관하고 다음 단계로 이동
  - 회원가입 화면으로 가는 링크
- 백엔드 추가
  - 내 계정 보기 주소 하나 (토큰 필요, user_id 와 username 반환)
  - 테스트 한 개 — 가입해서 받은 토큰으로 부르면 그 username 이 돌아온다
- 다음 단계 판정
  - 확정된 성향이 없으면(내 성향 보기가 404) 성향 설문으로
  - 있으면 전략 요청으로
- 완료 기준
  - 가입 때 받은 토큰으로 인증과 로그인이 된다
  - 틀린 토큰이면 인증 실패 사유가 뜨고 로그인 버튼이 눌리지 않는다

## 3단계 — 성향 설문, 성향 결과 화면

- 설문 화면
  - 문항 7개를 서버에서 받아 문항마다 선택지 라디오 버튼으로 표시
  - 7문항 모두 골라야 제출 버튼이 눌린다
  - 제출하면 답 보내기 → 성향 확정을 차례로 부르고 결과 화면으로 이동
- 결과 화면
  - 성향 번호와 이름(1 안정투자형 ~ 5 공격투자형), 기준표 버전, 확정 시각 표시
  - "다시 설문하기" 링크와 "전략 만들기로" 버튼
- 완료 기준
  - README 의 예시 답(A3 일곱 개)을 고르면 3 위험중립형이 나온다
  - 새로고침해도 결과 화면이 내 성향 보기로 같은 값을 보여 준다

## 4단계 — 전략 요청, 진행 상황, 되묻기, 완료 화면

- 전략 요청 화면
  - 자연어 입력창 한 개, 보내기 버튼
  - "2분 이상 걸립니다" 문구
  - 보내면 작업 번호를 받아 진행 상황 화면으로 이동
- 진행 상황 화면
  - 작업 번호와 현재 상태(대기, 진행, 완료)를 받는 대로 한 줄씩 쌓아 표시
  - 끝나면 결과에 따라 이동
    - completed → 완료 화면
    - need_answer → 되묻기 화면
    - failed → 이유를 그대로 보여 주고 "다시 요청" 링크
    - timeout → 시간 초과 문구와 "다시 요청" 링크
- 되묻기 화면
  - 서버가 준 질문 문장 표시
  - 선택지가 있으면 선택지 버튼, 없으면 자유 입력창
  - 답하면 session_id 와 답을 실어 다시 요청하고 진행 상황 화면으로 이동
  - "30분이 지나면 처음부터 다시 요청해야 합니다" 문구
- 완료 화면
  - 전략서 번호(spec_id)와 종목 수 표시
  - 전략서 내용(종목, 비중 범위, 리밸런싱, 신호 규칙) 자리는 "추후 구현 예정" 문구로 비워 둠
  - "다음 — 하드캡" 버튼
- 완료 기준
  - "안전하게 채권 위주로 굴리고 매달 정리해줘" 로 끝까지 가서 spec_id 를 본다
  - 방향이 없는 문장("알아서 해줘")으로 되묻기 화면이 뜨고, 답하면 이어진다
  - 성향이 없는 계정으로 요청하면 실패 이유가 뜬다

## 5단계 — 하드캡 화면 (빈 화면)

- 하는 일
  - "시스템 상한선(하드캡) 검사는 구현 예정입니다" 문구
  - 지금은 상한선을 넘는 전략서도 그대로 저장된다는 한 줄
  - "다음 — 백테스트" 버튼
- 완료 기준
  - 완료 화면에서 이동하고, 다음 화면으로 넘어간다

## 6단계 — 백테스트 화면

- 하는 일
  - 기존 저장된 결과 파일을 읽어 표시
  - "방금 만든 전략서가 아니라 미리 저장된 백테스트 결과입니다" 문구
  - 차트 없이 숫자 목록으로만 — 기간, 전략 / 대조군 / 시장 각각의 최종 수익률과 최대 낙폭
  - 기존 /report 로 가는 링크
  - "다음 — 최종 확인" 버튼
- 완료 기준
  - 화면에 숫자가 나오고, 그 숫자가 어떤 데이터에서 왔는지 한 줄로 적혀 있다

## 7단계 — 최종 확인 화면

- 하는 일
  - 지금까지의 결과 요약 — 아이디, 성향, spec_id, 백테스트 요약 숫자
  - 승인 버튼 — 서버가 501 이므로 누르면 "승인 기능은 구현 예정" 과 서버 응답을 그대로 표시
  - "승인하면 전략서를 고칠 수 없습니다" 문구
  - "다음 — 관점 판단" 버튼
- 완료 기준
  - 앞 단계 값이 한 화면에 모이고, 승인 버튼이 501 을 그대로 보여 준다

## 8단계 — 관점 판단 화면

- 하는 일
  - 세 관점(시장분석, 뉴스 감성, 시장온도)과 통합 신호를 설명하는 문구
  - 각 관점의 현재 상태 한 줄 — 시장분석과 시장온도는 가짜 점수, 감성은 항상 중립
  - "관점 판단 결과 조회는 구현 예정입니다" 문구
  - 처음 화면(전략 요청)으로 돌아가는 링크
- 완료 기준
  - 흐름의 마지막 화면으로 도달하고, 처음으로 돌아갈 수 있다

## 9단계 — 기존 화면 정리

- 시작 화면(/)
  - 지금의 스캐폴드 링크 목록을 로그인 여부에 따른 이동으로 바꾼다
  - 개발용 링크(/health, /report)는 맨 아래 목록으로 남긴다
- 상태 화면(/health) — 그대로 둔다
- 리포트 화면(/report) — 그대로 둔다. 백테스트 화면에서 링크로만 연결
- 완료 기준
  - 처음 접속하면 로그인 화면으로, 로그인한 상태면 이어서 할 화면으로 간다

---

## 전체 완료 기준

- 새 브라우저에서 가입 → 로그인 → 설문 → 전략 요청 → (되묻기) → 완료 → 하드캡 → 백테스트 → 최종 확인 → 관점 판단까지 버튼만으로 이어진다
- 모든 화면에 디자인 요소가 없다. 기본 HTML 만 쓴다
- 새 의존성이 없다
- 서버 오류가 어느 화면에서 나든 사용자에게 그대로 보인다

## 범위 밖

- 디자인 — 추후 별도 작업
- 하드캡 검사, 승인, 백테스트 API, 관점 판단 API 본체 — 각 담당 라인
- 토큰 자동 재발급 — 만료되면 다시 로그인한다
- 전략서 목록, 여러 전략서 관리

## 리스크

- 전략 생성이 2분 넘게 걸려 화면에서 멈춘 것처럼 보인다 — 상태 줄을 받는 대로 쌓아 보여 주는 것으로 대응
- 진행 상황 스트림은 10분에 끊긴다. 로컬 LLM 이 느리면 timeout 이 난다
