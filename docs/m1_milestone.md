# M1 전략 컴파일 — 마일스톤

- 재원 담당. 단계별 목표와 **"끝났다"고 말할 수 있는 기준**을 적는다
- 항목별 구현 목록과 기존 코드 조사 결과는 `docs/m1-todo.md`
- 데이터·기존 구현 현황은 `docs/data-status.md`
- 작성 2026-09-20 기준

---

## 목표

- 사용자가 쓴 문장을 **전략서(Spec JSON)** 로 바꾸고, 그 결과를 데이터베이스에 남기는 것까지
- 전략서가 지켜야 할 범위(성향별 종목 상한)는 **만들 때부터 박아 넣는다**
  - 나중에 검사해서 걸러내는 게 아니라, 애초에 어길 수 없는 스키마를 LLM 에 준다

### M1 이 끝났다고 말할 수 있는 조건

- 자연어 한 줄을 넣으면 → 성향에 맞는 전략서가 나오고 → 데이터베이스에 저장된다
- 샘플 10건이 전부 통과한다
- 같은 입력을 두 번 넣으면 같은 후보 종목과 같은 허용범위가 나온다
  - LLM 출력 자체는 흔들릴 수 있지만, **후보 선정과 범위 계산은 흔들리면 안 된다**

## 0단계 — 바닥 (완료, 2026-09-20)

- 표 구조 36개 생성. `db/init/` 이 안 돌던 문제를 볼륨 재생성으로 해결
- 기준표 적재 — 공통 상한선 1 · 프리셋 30(5×6) · 묶음 상한 25 · **종목 173**
- 종목 → 등급 → 성향별 상한 조회가 실제로 이어지는 것 확인
- `POST /auth/signup` 추가. Swagger 에서 계정을 만들어 바로 토큰을 받는다
- Swagger 설명 전면 한글화. 토큰 만료 30일로 늘려 둠

## 선행 안건 — 코드보다 먼저 정해야 하는 것

- **① 위험등급 173종목 재배정** ← 가장 급함
  - 지금 값은 3년 변동성 자동 산정. 협회 공시 등급이 아님
  - 173종목 중 87개가 G1(초고위험)에 쏠려 있고 KODEX 200 도 G1
  - 그대로 두면 안정형이 담을 수 있는 주식형이 14종목뿐. 위험중립형도 국내 대표지수를 못 담음
  - **2·4단계의 결과가 전부 이 값에 달려 있다**
- **② 되묻기 대화 상태를 어디 둘지**
  - 스키마에 대화 세션 표가 없음. 표를 추가할지, 메모리·Redis 로 버틸지
  - 표 추가는 임의로 못 함(규칙). 6단계 착수 전까지 결정
- **③ 비중 클램프를 M1 이 할지 Validator 가 할지**
  - 성격상 검증 2단인데 담당이 안 정해짐. 5단계 전까지 결정
- **④ 파이프라인 라이브러리 의존성 위치**
  - 지금 설치돼 있지 않음. M1 전용 묶음으로 뺄지 기본에 넣을지
  - api·worker·beat 가 이미지 하나를 공유함. 6단계 전까지 결정
- **⑤ 레버리지·상장폐지 종목 추가**
  - 지금 종목 표에서 통째로 빠져 있음(수집 단계에서 걸러짐)
  - 데모의 "생성 자체가 불가능" / "상장폐지 차단" 장면에 필요. 7단계 전까지

## 1단계 — 성향 판정

- **하는 일** (`m1-todo` §2)
  - 설문 문항과 점수 매핑 정의
  - 점수 합산 → 성향 1~5 산출
  - `POST /profile/survey` · `POST /profile` · `GET /profile/me` 본체 채우기
- **재사용할 것**
  - 라우터 3개의 경로·응답 형식·인증이 이미 열려 있음. **본체만 채운다**
  - 성향별 현금 하한·라벨은 `backtest/policy.py` 에 이미 있음. 다시 정의하지 말 것
- **완료 기준**
  - Swagger 에서 설문 제출 → 성향 확정 → `GET /profile/me` 가 등급을 돌려줌
  - `risk_profiles` 에 행이 생기고, 어떤 기준표 버전으로 정했는지 같이 기록됨
  - 같은 답을 넣으면 항상 같은 등급이 나옴
- **막는 것 없음. 여기부터 시작한다**

## 2단계 — 프리셋 조회기

- **하는 일** (`m1-todo` §3)
  - (성향, 종목등급) → 허용 상한 조회
  - 성향 → 자산군·업종·국가 상한 조회
- **핵심 — 새로 만드는 게 아니라 옮기는 것**
  - 같은 수치가 이미 세 군데 있음: 시드 SQL · `backtest/policy.py` · 프론트
  - `policy.py` 머리에 *"최종적으로는 DB 에서 읽어야 한다. 그때는 이 파일의 상수만 조회 함수로 바꾸면 된다"* 고 적혀 있음
  - **함수 이름과 반환 모양을 기존 것에 맞추면 백테스트 호출부를 안 건드려도 된다**
- **완료 기준**
  - 조회 함수가 DB 를 읽고, 시드 수치와 한 칸도 틀리지 않음
  - `policy.py` 의 상수가 사라지고 사본이 3벌 → 2벌로 줄어듦
  - 백테스트가 예전과 같은 결과를 냄 (두 러너 대조 통과)
- **선행 안건 ① 이 끝나야 결과가 의미를 가짐.** 코드는 먼저 짜도 됨

## 3단계 — BBL (블록 라이브러리)

- **하는 일** (`m1-todo` §1)
  - 블록 시드 작성 — 지표 / 필터 / 리밸런싱 규칙 / ETF 특성
  - 태그 체계 정의
  - 검색 함수 (`app/repositories/bbl.py`)
- **제약**
  - 지표 블록 이름은 **`features.py` 의 지표 9개 안에서만.** 없는 지표를 넣으면 지표 버전을 올려야 하고 그건 M3 영역
  - 렌즈 블록은 보류 — 렌즈 목록 정의가 아직 없음(M3 조율 필요)
- **완료 기준**
  - 태그로 블록을 찾을 수 있고, 같은 질의에 항상 같은 순서로 나옴
  - 블록이 수십 개 규모면 **태그 매칭만으로 충분.** 벡터 검색은 못 잡는 사례가 나올 때 켠다
- **1·2단계와 독립. 병행 가능**

## 4단계 — 의도 파악과 후보 선정

- **하는 일** (`m1-todo` §5 §6 §7)
  - 자연어 → 구조화된 의도 추출, 태그 추출, 종목 언급 판별
  - 종목 후보 선정 — 언급됐으면 매칭, 아니면 업종·자산군으로 추림
  - 허용 상한이 0인 종목 제거
  - 전략서 스키마에 **종목별 최소·최대 비중을 동적으로 주입**
- **재사용할 것**
  - 스키마 생성·export 함수와 생성된 스키마 파일이 이미 있음
  - **새로 만들 것은 "종목별 상하한 주입" 한 겹뿐.** 스키마를 손으로 다시 쓰면 계약이 두 벌이 됨
- **완료 기준**
  - 문장 하나를 넣으면 후보 종목 목록이 나오고, 각 종목에 성향별 상한이 붙음
  - 담을 수 없는 종목(상한 0)이 후보에서 빠짐
  - 같은 문장 두 번에 같은 후보가 나옴
- **선행 안건 ① 이 반드시 먼저.** 등급이 틀린 채로 만들면 결과를 보고 코드를 의심하게 됨

## 5단계 — 전략서 생성과 후처리

- **하는 일** (`m1-todo` §8 §9)
  - 컴파일 프롬프트 설계 (의도 + 블록 + 후보 종목 + 제약)
  - LLM 호출 — 동적 스키마를 넘겨 형식을 강제
  - 결과 파싱 → 허용범위로 접기 → 원출력과 조정 여부 보존 → 저장
- **주의**
  - **Ollama 는 형식 강제가 약해 스키마 위반이 실제로 난다.** 로컬 개발은 전부 Ollama 이므로 파싱이 유일한 방어선
  - 정식 실측은 **vLLM 쪽에서** 해야 함(기준 문서 지시). GPU 있는 팀원 협조 필요 — **10월**
  - 범위를 접는 계산은 `policy.py` 에 이미 있음. 다시 쓰지 말 것 (선행 안건 ③)
  - 저장 상태는 `draft` 까지만. 승인 상태가 되면 수정이 물리적으로 막힘
- **완료 기준**
  - 전략서가 형식 검사를 통과하고 데이터베이스에 저장됨
  - LLM 이 범위를 벗어난 비중을 냈을 때 접히고, **접었다는 사실과 원래 값이 함께 남음**
  - 같은 전략서를 M4 백테스트가 읽어서 돌릴 수 있음

## 6단계 — 파이프라인과 되묻기

- **하는 일** (`m1-todo` §10 §4)
  - 상태 머신 정의, 노드 연결, 되묻기 루프
  - `compile_spec` 작업의 속을 갈아끼움
- **격리 방침**
  - **닿는 접점은 한 군데.** 지금 3초 대기 후 끝나는 더미의 본체만 바꾼다
  - `app/m1/` 한 곳에 몰고 의존을 단방향으로 고정. 기존 모듈이 이쪽을 import 하지 않음
  - **작업 이름 `compile_spec` 은 바꾸지 않는다.** 라우터와 프론트가 이 이름에 붙어 있음
- **완료 기준**
  - Swagger 에서 요청 → 작업 번호 → 진행 상황 스트림으로 완료와 결과를 받음
  - 정보가 모자라면 되물어서 답을 받아 이어감
- **선행 안건 ② ④ 가 먼저**

## 7단계 — 샘플 10건

- **하는 일** (`m1-todo` §11)
  - 입력 문장 + 기대 전략서 쌍 10건
  - 전 구간 검증 테스트
- **10건에 반드시 넣을 것**
  - 성향별로 결과가 달라지는 쌍 — 같은 문장을 안정형과 공격형이 냈을 때
  - **실패해야 하는 입력 최소 2건** — 안정형에게 레버리지 요청, 상장폐지 종목 지정
    - 선행 안건 ⑤ 가 끝나야 만들 수 있음
  - 정보가 모자라 되묻게 되는 입력 1건
- **완료 기준**
  - 테스트가 CI 에서 돎. LLM 호출이 필요한 것은 `requires_ollama` 표시를 달아 기본 실행에서 뺌
