이 목록에 없는 것은 docs/strategy-spec-v0.2.md 를 그대로 따른다.

| v0.2 항목 | 데모에서는 | 이유 |
|---|---|---|
| DB (instruments, tax_rates 등 표) | JSON/YAML 파일로 대체 (data/, config/) | DB 서버 없이 돌린다 |
| 종목 = 한국 상장 주식·ETF 전체 | data/tickers.json 시드 목록만. 목록에 없는 한국 종목은 "목록에 없어요, 다른 종목?"으로 되묻기 | 전체 종목 원장이 아직 없다 |
| 종류로 말한 종목("반도체주", "코스피 상위 10종목") | 되묻기: "데모에서는 종목 이름으로만 받아요. 어떤 종목으로 할까요?" | 업종·시가총액 이력 데이터가 없다 |
| 배당 | 반영하지 않음. 배당 낱말이 있으면 결과에 "데모에서는 배당 미반영" 표시 | 배당 이력 데이터가 없다 |
| 거래정지·정리매매 처리 | 하지 않음. 시가 0 인 날만 제외 | 이력 데이터가 없다 |
| 시장 이전·종목명 변경 이력 | 현재 값만 사용 | 이력 데이터가 없다 |
| 그 밖의 ETF 차익 15.4% | 넣는다 (tickers.json 에 tax_type) | v0.2 그대로 |
| VIX | FinanceDataReader 로 받을 수 있으면 넣고, 안 되면 빼고 보고 | 데이터 출처 확인 필요 |
| 평가 데이터셋 120건 | 개발용 40건만 먼저 (바로 진행 20 · 되묻기 10 · 거절 10) | 최종 평가용 80건은 팀이 따로 라벨링 |
| LLM 직접 코드 생성 비교 | 마지막 단계(선택) | 핵심 흐름 먼저 |
| "언제 살까요?" 되묻기의 "처음부터 갖고 시작" 선택지 | 뺀다. 선택지는 "조건이 반대가 되면 다시 사기"만 (손절·보유 일수만 있으면 "문장을 고쳐서 다시 입력") | v0.2 전략서에 '첫날 사서 시작'을 적을 칸이 없다. **팀 안건**: 칸을 추가할지(rules.start_holding 등, 스키마 변경 = 전원 합의), 선택지를 v0.2 에서도 뺄지 |

## 팀 안건 · 데모에서 정한 것

| 항목 | 데모에서 정한 것 | 확인할 것 |
|---|---|---|
| "처음부터 갖고 시작" | 위 표대로 뺐다 (2026-11-02) | 스키마에 칸을 둘지 |
| 5단계 "너무 자주 사고팜" 기준 | 기간 거래일 대비 사고팔기 횟수 ≥ 0.2 (평균 5거래일에 한 번 이상)면 경고 (core/validate.py TOO_FREQUENT_RATIO) | **확정 (2026-11-02)** |
| NO_DATA 과거 데이터 길이 | 계산식대로 센다: n일 이평은 n-1, RSI·수익률·변동성·거래량 비율은 n, '~하는 순간'은 +1. 종목은 기간 시작 전 1거래일 이상 | v0.2 는 "120일 이평이면 120거래일 앞부터" (1일 차이) |
| 세력·바닥·고점·꼭지 | 정량 정의가 없는 말이라 되묻기에서 거절(UNKNOWN_INDICATOR)로 옮김 (data/expressions.json). 이 이유를 표의 note 에 적으면 LLM 프롬프트에 들어가 '과매도'까지 "정량 정의 없음"으로 적는 일이 생겨(2026-11-02 관찰) 여기에만 적는다 | 개발용 문장 clarify-03 라벨을 reject(UNKNOWN_INDICATOR)로 바꿈 (2026-11-02 확정) |
| 표현 표 추가 (2026-11-02 확정) | "올라가면" → cross_above, "{p}% 떨어지면 손절" → <=, "{p}% 오르면 익절" → >=, "{n}거래일 지나면 팔아" → 보유 일수 >=. 조건 구절이 동사 구절보다 먼저 (LLM 근거가 "10% 떨어지면"까지만이어도 원문의 바로 뒤 낱말까지 보고 찾는다) | — |
