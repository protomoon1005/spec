> 재원 담당. 세부 기획 전 윤곽 잡기용.
>
> 각 항목의 `▸` 는 **기존 구현 조사 결과**다(2026-09-20 기준).
> 중복 설계를 막으려고 붙였다. 데이터 현황 전반은 `docs/data-status.md` 참고.

## 0. 구현 방침 — M1 전용으로 격리한다

파이프라인 라이브러리를 기존 코드 전체에 끼워넣지 않는다. **닿는 접점은 한 군데뿐이다.**

```
POST /specs/compile → 작업번호 발급 → Celery 태스크 compile_spec → 진행상황 스트리밍
                                            ↑
                                   여기 속만 갈아끼운다
```

라우터·인증·작업번호·스트리밍은 이미 동작한다(지금은 3초 더미). 그 더미 본체를
그래프 호출로 바꾸는 것이 통합 작업의 전부다.

**격리 지점 셋**

1. **의존성** — `backend/pyproject.toml` 에 M1 전용 그룹을 판다(백테스트용·판단계층용
   그룹이 이미 같은 방식으로 있다).
   주의: `api`·`worker`·`beat` 가 **이미지 하나를 공유**하고 그 이미지는 `[dev]` 만
   설치한다. 그룹만 파면 컨테이너에 안 깔린다 — Dockerfile 설치 줄도 같이 고쳐야 하고,
   그러면 API 쪽에도 함께 들어간다. 기존에 무거운 것들을 뺀 이유는 용량이었으니
   (파이토치 2.5GB 등), 순수 파이썬 라이브러리면 용량 재보고 판단한다.
2. **디렉터리** — `app/m1/` 하나로 몰고 의존을 단방향으로 고정한다.
   `app/m1/` → `app/llm/` · `app/contracts/` · `app/repositories/` 만 본다.
   기존 모듈이 `app/m1/` 을 import 하지 않는다. (백테스트 러너 ↔ 판단 계층 접합부가
   이미 같은 규칙으로 돼 있다.)
3. **접점** — 태스크 **함수 안에서** import 한다. 그룹이 안 깔린 환경에서도 앱이 뜬다.

**격리 ≠ 재구현.** 아래 넷은 `app/m1/` 안에서 새로 만들지 말고 바깥 것을 호출한다.

| 다시 만들지 말 것 | 이유 |
|---|---|
| 프리셋·하드캡 수치 | 사본이 이미 3벌(DB 시드 / 파이썬 / 프론트). 4벌째는 어긋났을 때 정본을 잃는다 |
| Spec 계약 모델·스키마 파일 | 검증·백테스트·프론트가 전부 이걸 본다 |
| LLM 클라이언트 | 두 백엔드 분기가 이미 돼 있다 |
| 태스크 이름 `compile_spec` | 라우터와 프론트가 이 이름에 붙어 있다 |

**함정** — `app/` 전체를 훑는 as_of 검사 스크립트가 CI에서 돈다. 가드 대상 세 테이블
이름이 `app/repositories/` 밖에 문자열로 나오면 실패하고, **설명문(docstring)도 걸린다.**
`app/m1/` 도 사정권이다. 기존 판단 계층 모듈들이 그래서 설명을 `#` 주석으로 쓴다.

## 1. BBL (Building Block Library)

- BBL 시드 데이터 작성 (기술적 지표 / ETF 특성 / 리밸런싱 규칙 / 렌즈 / 필터)
    - ▸ 테이블 둘(`bbl_blocks`/`bbl_tags`)은 있고 **시드 0행**. 목데이터 없다.
    - ▸ 외부 API로 받아올 성질이 아니다 — 손으로 쓰는 카탈로그다.
      블록 종류는 스키마에서 5종으로 못 박혀 있다(지표/필터/리밸런싱/렌즈/ETF특성).
    - ▸ **지표 블록 이름은 마음대로 쓰면 안 된다.** 허용 집합의 정본은
      `views/market/features.py` 의 피처셋 v0.1-ta9 아홉 개다. 없는 지표를 넣으면
      피처셋 버전을 올려야 하고 그건 M3 영역이다.
    - ▸ **렌즈 블록은 보류.** 감성 쪽 렌즈 목록 정의가 아직 아무 데도 없다(M3 조율 필요).
- BBL 태그 체계 정의
    - 세부 대화 예정.
    - ▸ `bbl_tags` 는 (블록, 태그) 평면 테이블이라 계층도 네임스페이스도 스키마가 안 준다.
      컬럼 추가는 금지 규칙이므로 `asset:equity` 같은 **접두어 규약**으로 푸는 수밖에 없다.
- BBL 임베딩 생성 스크립트
    - ▸ 칸은 768차원 고정이고 벡터 색인도 이미 걸려 있다. **차원을 바꾸면 칸 타입 변경 +
      색인 재생성**이라 되돌리기 비싸다 — 768을 내는 모델 중에서 골라야 한다.
    - ▸ 뉴스 쪽이 쓰는 한국어 문장 임베딩 함수가 정확히 768이고 정규화까지 해서 낸다.
      **그대로 호출하면 새 의존성 0.** (판단계층 그룹 설치 필요)
    - ▸ 하는 일은 제목+설명 이어붙여 임베딩 → 칸에 갱신. 전체 재생성으로 짠다.
      **시드 SQL에 벡터 값을 박지 말 것** — 텍스트를 고치면 다시 못 만든다.
- BBL 검색 repository (`app/repositories/bbl.py`) — 태그 매칭 + 벡터 유사도
    - ▸ **as_of 가드 대상이 아니다.** 가드는 피처·거시·관점가중치 세 테이블뿐이다.
      시점 인자를 강제할 필요 없다(계정 조회 리포지토리가 같은 선례).
    - ▸ **벡터 검색 쿼리는 베낄 게 있다** — 뉴스 유사기사 조회가 이미 돌아간다.
    - ▸ 재현성: 정렬 기준에 블록 식별자를 tie-break 로 항상 넣는다. 비활성 블록 제외.
    - ▸ 태그 점수와 벡터 점수를 가중합하지 말 것. 태그로 거르고 벡터로 정렬, 순서대로.
    - ▸ 블록이 수십 개 규모면 태그 매칭만으로 거의 잡힌다. **벡터는 나중에 켜도 된다** —
      칸과 색인이 이미 있어서 붙이는 비용이 스크립트 하나다.

    - ▸ 없다. 직접 만든다.

    - ▸ **경로·응답모델·인증·설문 항목 모델이 이미 다 있다**(본체만 501).

## 3. 프리셋 조회기

- 프리셋 조회 repository — (risk_level, risk_tag) → allowed_min/max
- 그룹캡 조회 — risk_level → 자산군별 상한
    - ▸ **중복 위험 최상.** `backtest/policy.py` 에 이미 전부 있다 —
      프리셋 5×6 표, 자산군 상한, 섹터 0.30, 국가 0.50, 하드캡 v0.1, 조회 함수 셋.
      같은 값이 프론트 쪽에도 있다.
    - ▸ 그 파일 머리에 이렇게 적혀 있다 — *"원본은 db/seeds 이고, 최종적으로는 DB에서
      읽어야 한다. 그때는 이 파일의 상수만 조회 함수로 바꾸면 된다."*
    - ▸ **즉 §3은 새로 만드는 일이 아니라 그 상수를 DB 조회로 바꾸는 일이다.**
      그러면 사본이 3 → 2로 줄고, 따로 만들면 4로 는다.
      함수 이름과 반환 모양을 기존 것에 맞추면 백테스트 호출부를 안 건드려도 된다.

## 4. 되묻기

- 대화 세션 상태 모델 (CompileState)
    - ▸ **막힘.** 대화 세션을 저장할 테이블이 스키마에 없다. *"스키마에 없는 컬럼을
      편의상 추가하지 않는다, 필요하면 먼저 묻는다"* 규칙이 걸린다.
      **선택지를 정리해 팀에 올릴 항목**(메모리/Redis로 버틸지, 테이블을 추가할지).
- 필수 정보 누락 판별 로직
- 되묻기 질문 생성 (LLM)
- 사용자 응답 병합
    - ▸ 비동기 뼈대는 있다 — 작업 접수·번호 발급·진행상황 스트리밍이 실제로 동작한다.
      되묻기 왕복을 이 위에 얹을지 동기 요청으로 처리할지는 설계 선택.

## 6. ETF 후보 선정

- 종목 직접 언급 시 → etf_master 매칭 + 동일 섹터 보충
- 종목 미언급 시 → 섹터/자산군 기반 필터링
- 프리셋 허용범위 0.00인 ETF 제거
    - ▸ **막힘. 종목 원장이 0행이다.** 시드 표 파일은 60종목 중 4행뿐이고 분류 칸이 비었다.
      자산군 칸이 필수값이라 비어 있는 동안은 데이터베이스에 한 줄도 안 들어간다.
    - ▸ 다만 **173종목이 분류까지 끝난 파일이 이미 있다** (`frontend/data/universe.csv` —
      종목코드·이름·자산군·섹터·국가·위험등급). 원장을 채우는 가장 싼 길은 이 파일의 승격이다.
    - ▸ 그 전에 **팀 결정 두 가지**가 필요하다. 아래 "먼저 풀 안건" 참고.

## 7. 스키마 동적 조립

- SpecV0_1 JSON Schema에 종목별 minimum/maximum 동적 주입
- 프리셋 범위 반영된 커스텀 스키마 생성 함수
    - ▸ **절반은 이미 있다.** 스키마 생성·export 모듈이 있고 **생성된 스키마 파일도
      커밋돼 있다**(`app/contracts/schema/spec_v0_1.schema.json`). 그 파일 주석에
      *"M1의 structured outputs가 이 파일을 직접 입력으로 쓴다"* 고 적혀 있다.
    - ▸ **새로 만들 것은 "종목별 상하한 주입" 한 겹뿐이다.** 기존 생성 함수를 호출해
      받은 결과에 값을 끼워 넣는다. 스키마를 손으로 다시 쓰면 계약이 두 벌이 된다.

## 8. LLM Spec 생성

- 컴파일 프롬프트 설계 (의도 + BBL 블록 + ETF 후보 + 제약)
- `LLMClient.generate_json()` 호출 — 동적 스키마 전달
- vLLM guided_json / Ollama format 양쪽 검증
    - ▸ **클라이언트는 완성돼 있다.** 한 함수로 두 백엔드 모두 지원한다. 새로 만들지 말 것.
    - ▸ Ollama 쪽은 **제약 디코딩이 약해 스키마 위반이 실제로 난다**(구현체 설명에 명시).
      로컬 개발은 전부 Ollama이므로 §9 파싱이 유일한 방어선이다.
      정식 실측은 vLLM 쪽에서 한다는 것이 기준 문서 지시다.

## 9. 후처리

- Pydantic SpecV0_1 파싱 + 검증
    - ▸ **필수.** 계약 모델이 이미 있으니 그대로 파싱한다. 위 Ollama 사정 때문에 뺄 수 없다.
- LLM 원출력 비중 → 프리셋 범위 클램프 + was_adjusted 플래그
    - ▸ **필수.** 표 칸(원출력 하한·상한·조정여부)이 이것 하나 때문에 있다.
    - ▸ **계산식을 다시 쓰지 말 것** — 프리셋 상한과 하드캡을 순서대로 접는 함수가
      `backtest/policy.py` 에 이미 있다. §3 처리와 같이 가는 문제다.
    - ▸ 경계 확인 필요: 클램프는 성격상 검증 2단이다. 기준 문서가 Validator 본체를
      인프라 범위 밖으로 뺐을 뿐 **담당을 안 정했다.** M1이 하면 나중에 중복된다 — 팀 확인.
- DB 저장 (strategy_specs + spec_universe)
    - ▸ 필요하지만 **§6에 막혀 있다** — 종목 칸이 원장 참조라 원장이 비면 저장이 안 된다.
      순서상 뒤로 미루고, 그전까진 Spec 객체 반환까지만 해도 파이프라인은 돈다.
    - ▸ 상태는 `draft` 로만 쓴다. 승인 상태가 되는 순간 트리거가 수정을 물리적으로 막고,
      그 이후 전이 절차가 아직 안 정해졌다(README 설계 구멍).
- ▸ 빠져 있는 것: **검증 실패 시 재생성/되묻기 루프.** 검증 로그 테이블이 있는데
  후처리가 안 쓴다. 데모에 실패 장면을 넣을 거면 여기에 걸려야 한다.

## 먼저 풀 안건 (코드가 아니라 결정이 필요한 것)

우선순위 순.

1. **173종목 위험등급 사람 검토** — 지금 값은 3년 변동성 자동 추정이다.
   예: KODEX 200이 변동성 38%로 **G1(초고위험)** 을 받았는데, 프리셋 표에서 G1은
   안정·안정추구·위험중립 세 성향 모두 상한 0.00이다. 그대로 쓰면 **보수적 투자자에게
   국내 대표지수 ETF 후보가 아예 안 남는다.** 실무 기준으로는 보통 2등급이다.
   위험등급 자동 추정은 원래 금지 규칙이고, 수집 기록 파일에도 "협회 공시 수치가
   아니다"라는 경고가 붙어 있다. **§3·§6·§7이 전부 이 칸을 읽는다 — M1 최대 선행 과제.**
2. **원장에 데모용 종목 추가** — 레버리지·상장폐지 종목이 그 파일에서 의도적으로
   걸러져 있다("3년 이력" 필터에 자동 탈락). 없으면 데모의 "생성 자체가 불가능" /
   "상장폐지 종목 차단" 두 장면을 보일 수 없다.
3. **대화 세션 상태를 어디 둘지** (§4) — 스키마 추가 여부 판단.
4. **클램프 담당이 M1인지 Validator인지** (§9).
5. **파이프라인 라이브러리 의존성 위치** (§10/0장).
