# 사람을 위한 설명서 — 시스템은 어떻게 흘러가는가

- 코드를 열지 않고 시스템 전체 흐름을 이해하기 위한 설명서
- 파일 이름, 함수 이름은 쓰지 않음. 기능 단위로 사용자 행동과 시스템 내부 동작을 순서대로 정리
- 각 기능마다 현재 구현 상태를 함께 표기 (2026-09-23 기준)
  - 동작함: 실제로 쓸 수 있음
  - 일부: 흐름은 돌지만 가짜 데이터를 쓰거나 일부만 구현됨
  - 없음: 자리와 설계만 있고 본체는 아직 없음

---

## 0. 한 줄 요약

- 사용자가 자연어로 투자 요청을 하면 시스템이 전략서라는 정해진 양식으로 바꿈
- 규칙 검사를 통과한 전략서만 정해진 계산대로 매번 사고팔 비중을 정함
- 실제 돈은 쓰지 않는 모의투자

## 1. 전체 흐름

### 1.1 단계 순서

1. 회원가입과 로그인
2. 투자 성향 설문으로 성향 1~5 확정 (안정투자형 ~ 공격투자형)
3. 전략 만들기: 자연어 요청을 받아 전략서로 변환 후 저장 (AI 사용)
4. 전략 검사: 양식, 존재 여부, 논리, 시스템 상한선 검사 (AI 미사용)
5. 사고팔 판단: 시장분석, 뉴스 감성, 시장온도 세 관점 점수를 하나의 신호로 통합 (학습 모델 또는 규칙, 대화형 AI 아님)
6. 주문 내기: 신호를 종목별 비중으로 바꾸고 묶음 상한 적용 후 주문 생성 (AI 미사용)
7. 결과 보기: 백테스트와 리포트 화면

### 1.2 핵심 원칙

- 재현성
  - 같은 입력을 넣으면 언제나 같은 주문이 나와야 함
  - AI 출력이 조금씩 달라도 종목 후보와 허용 비중 범위는 흔들리지 않게 설계
- 시점 무결성
  - 어떤 날의 판단은 그날까지 알 수 있었던 정보만 사용
  - 예: 2024년 3월 판단에 4월 주가가 섞이면 백테스트 결과 전체가 무의미해짐
  - 데이터를 꺼내는 창구를 한 곳으로 모으고, 그 창구가 기준 날짜 이후 데이터를 내주지 않도록 차단

### 1.3 AI 사용 범위

- 단계 경계가 곧 AI 사용 경계
  - 전략 만들기: 대형 언어모델 사용
  - 전략 검사: 사용 안 함
  - 사고팔 판단: 학습 모델 또는 규칙 사용, 대화형 AI는 사용 안 함
  - 주문 내기: 사용 안 함
- AI가 틀린 답을 내도 뒤의 검사와 주문 단계가 규칙으로만 움직이므로 위험한 주문이 나갈 수 없도록 하는 것이 설계 의도

## 2. 기능별 설명

### 2.1 회원가입과 로그인 (동작함)

- 이메일과 비밀번호로 가입하면 즉시 출입증(토큰) 발급
- 이후 거의 모든 요청에 출입증 필요. 없으면 거절
- 사용자 등급은 일반, 전문가, 관리자 세 가지
  - 현재는 가입 시 무조건 일반 사용자로 생성
  - 등급을 올리는 경로는 아직 없음
- 출입증 만료 시 재발급 요청으로 새 출입증 수령

### 2.2 투자 성향 판정 (동작함)

- 전략서를 만들기 전에 반드시 먼저 완료해야 함
- 성향에 따라 담을 수 있는 종목과 비중이 달라지기 때문

진행 순서

1. 설문 문항 7개 수령
   - 나이, 투자 기간, 투자 경험, 금융 지식, 수입원, 전체 자산 중 투자 비중, 감당 가능한 손실
   - 금융투자협회 표준 확인서 구성을 따름. 배점은 팀이 정한 값
2. 답변 제출. 같은 문항에 다시 답하면 마지막 답을 사용
3. 성향 확정 요청 시 점수를 합산해 5단계 중 하나로 판정
   - 1 안정투자형, 2 안정추구형, 3 위험중립형, 4 성장투자형, 5 공격투자형
   - 문항별 중요도가 다르며 감당 가능한 손실이 가장 크게 반영됨
4. 판정 결과는 덮어쓰지 않고 누적. 조회 시 가장 최근 결과 사용
5. 판정에 사용한 기준표 버전도 함께 기록
   - 기준표가 나중에 바뀌어도 과거 판정의 근거 추적 가능

성향 확정 시 자동으로 따라오는 값

- 종목 하나에 담을 수 있는 최대 비중 (종목 위험등급에 따라 다름)
- 최소로 남겨야 할 현금 비율 (안정형 20% ~ 공격형 5%)
- 주식, 채권, 원자재 각 묶음에 담을 수 있는 최대 비중

주의

- 요청 문장에 "공격적으로"라고 써도 성향은 바뀌지 않음
- 말 한마디로 자기 한도를 올릴 수 있으면 설문의 의미가 없어지기 때문

### 2.3 전략 만들기: 자연어에서 전략서로 (동작함)

- 시스템의 대표 기능. 사용자가 한 문장을 넣으면 전략서가 나옴

전략서에 들어가는 내용

- 담을 종목과 각 종목의 최소~최대 비중 범위
- 비중을 다시 맞출 시점 (예: 매달 첫 거래일, 비중이 5%p 벗어날 때)
- 사고팔 기준 (시장분석, 뉴스 감성, 시장온도 각각에 쓸 지표)
- 지켜야 할 제약 (최소 현금 등)

처리 방식

- 수 분이 걸리는 작업이라 요청 즉시 작업 번호만 반환
- 실제 처리는 뒤에서 별도로 진행
- 사용자는 작업 번호로 진행 상황을 실시간 확인

처리 순서

1. 성향 확인
   - 확정된 성향이 없으면 중단하고 설문을 먼저 마치라는 안내 반환
2. 요청 이해 (AI 사용)
   - 문장에서 키워드(배당, 안전하게 등), 업종(반도체, 2차전지 등), 자산군(주식, 채권, 원자재), 언급된 종목 이름 추출
   - AI는 자유롭게 쓰지 못하고 시스템이 준 목록 안에서만 선택
     - "따박따박 나오는", "월배당" 같은 다양한 표현이 모두 "배당" 하나로 정리됨
     - 목록에 없는 말은 버려져 엉뚱한 값이 다음 단계로 넘어가지 않음
   - 종목 이름은 들린 그대로 받아 적고 실제 종목 검색은 시스템이 수행
     - AI에게 종목코드를 맡기면 존재하지 않는 코드를 지어내기 때문
3. 되묻기 판정
   - 되묻는 경우는 세 가지
     - 종목 이름이 여러 종목과 일치하거나 찾지 못한 경우: 후보 목록을 보여주고 선택 요청
     - 방향에 대한 단서가 전혀 없는 경우: "안전하게, 배당, 특정 업종, 직접 고르기" 중 선택 요청
     - 조건에 맞는 종목이 하나도 없는 경우: 담을 수 없는 이유를 보여주고 다른 조건 요청
   - 질문 문구는 AI가 만들지 않고 미리 정해 둔 문구 사용
     - 빠르고, 매번 같고, 존재하지 않는 선택지를 지어내지 않음
   - 사용자가 답하면 처음 요청 뒤에 답을 이어 붙여 1번부터 다시 수행
     - "역시 채권 말고 주식으로"처럼 앞 내용을 뒤집는 답도 자연스럽게 반영
   - 대화 상태는 30분간 보관. 그 안에 답하지 않으면 처음부터 다시 요청해야 함
   - 같은 질문은 두 번 하지 않음. 두 번째에도 담을 종목이 없으면 실패로 종료
4. 담을 수 있는 종목 선정 (AI 미사용)
   - 사용자가 지목한 종목을 먼저 아래 순서로 검사하고, 걸리면 이유 하나를 기록
     1. 종목 목록에 존재하는가. 없으면 "찾을 수 없음"
     2. 현재 거래 중인가. 아니면 "상장폐지"
     3. 레버리지 또는 인버스인가. 시스템이 금지하면 "레버리지 금지"
     4. 해당 성향이 담을 수 있는 위험등급인가. 아니면 "이 성향은 담을 수 없음"
   - 지목 종목이 부족하면 업종과 자산군 조건으로 10개 안팎까지 보충
   - 각 후보에 해당 성향 기준 최대 비중을 부여
   - 같은 요청에는 항상 같은 후보가 같은 순서로 나옴
5. 전략서 작성 (AI 사용)
   - 시스템이 이번 요청 전용 양식을 생성
     - 양식에는 선정된 후보 종목만 들어갈 수 있음
     - 각 종목의 비중 칸에 허용 범위가 미리 고정됨
     - 사후 검사로 거르는 방식이 아니라 처음부터 규칙을 어길 수 없는 빈칸을 제공하는 방식
   - 전략서에 넣을 수 있는 값들의 사전(전략 블록)도 함께 제공
     - 리밸런싱 방식 6종, 지표 13종, 필터, ETF 특성 등
   - AI는 후보 중 무엇을 왜 고를지만 판단해 양식을 채움
6. 후처리와 저장 (AI 미사용)
   - 전략서 번호, 사용자 번호, 종목 이름은 AI 출력을 믿지 않고 시스템 값으로 덮어씀
   - 양식으로 막을 수 없는 항목만 다시 확인
     - 최소 비중이 최대 비중보다 크지 않은지
     - 최소 비중 합과 최소 현금의 합이 100%를 넘지 않는지 (넘으면 실행 불가능)
     - 같은 종목이 중복되지 않았는지
     - 후보 밖 종목이나 범위를 벗어난 비중이 없는지 (로컬 AI는 양식 강제가 약해 실제로 위반하는 경우 있음)
   - 통과 시 초안(draft) 상태로 저장
   - AI 최초 출력값과 최종 확정값을 함께 보관해 수정 여부 추적

결과 종류

- 완료: 전략서 저장됨
- 되묻는 중: 질문과 선택지 반환. 답을 보내면 이어서 진행
- 실패: 생성 불가. 이유를 함께 반환

### 2.4 전략 검사 (없음)

- AI가 만든 전략서가 확정되기 전 규칙만으로 네 단계를 통과해야 함
- 설계는 완료, 본체는 아직 없음

검사 단계

1. 양식 검사: 필수 칸, 타입, 범위 확인. 정의되지 않은 칸은 거부
2. 참조 검사: 사용한 블록 존재 여부, 종목 상장 여부, 가격 데이터 존재 여부 확인
3. 논리 검사: 최소 비중과 최대 비중의 관계, 목표 낙폭과 종목 변동성의 양립 여부, 리밸런싱 주기와 최소 간격의 모순 여부 확인
4. 시스템 상한선(하드캡) 적용
   - 한 종목 최대 비중, 최소 현금 등 모든 전략에 공통으로 걸리는 최종 방어선
   - 넘는 값은 상한선으로 낮추고 낮췄다는 사실을 기록

비중 범위 자동 보정

- 최소 비중 합이 너무 크거나 최대 비중 합이 너무 작아 어떤 배분도 불가능한 경우 발생 가능
- 이 경우 되묻지 않고 비율대로 늘리거나 줄여 자동으로 맞춤

현재 영향

- 이 단계가 없어 시스템 상한선을 넘는 전략서도 그대로 저장됨
- 성향별 상한은 전략 만들기 단계에서 이미 막히지만 시스템 공통 상한선은 적용되는 곳이 없음

승인 후 수정 금지 (동작함)

- 전략서가 승인되면 종목과 비중 변경을 데이터베이스가 물리적으로 차단
- 변경이 필요하면 새 전략서를 만들어야 함
- 알려진 문제: 이 잠금이 상태 값까지 고정해 "승인, 운용중, 종료"로의 전환도 막힘. 팀 확정 대기

### 2.5 사고팔 판단: 3관점과 신호 통합 (일부)

- 판단 시점마다 종목별로 더 담을지 덜 담을지를 -1 ~ +1 사이 신호 하나로 산출

세 관점

- 시장분석
  - 가격 지표 9개 사용 (수익률, 이동평균 이격도, 상대강도, 변동성, 거래량 비율 등)
  - 지표 계산은 완성
  - 점수를 내는 모델이 아직 없어 고정된 가짜 점수 사용
- 뉴스 감성
  - 업종별 뉴스 기사의 긍정, 부정 판단
  - 뉴스 수집 기능이 제거되었고 과거 기사도 확보 불가
  - 항상 "판단 불가(중립)" 반환
- 시장온도
  - 거시지표 사용 (변동성 지수, 신용 스프레드, 환율, 지수 추세)
  - 위험선호, 위험회피 판정 규칙은 완성
  - 판단 흐름에는 아직 가짜 점수로 연결됨

관점 공통 사항

- 점수와 함께 "이 점수가 맞을 확률"도 산출. 이후 관점별 성적 채점에 사용
- 점수의 근거도 기록 (어떤 지표가 얼마나 기여했는지, 어떤 기사를 참고했는지 등)
- 화면의 판단 근거 탭이 이 기록을 보여주는 구조

시장온도 판정 방식

- 거시지표 네 개가 각각 위험 쪽인지 안전 쪽인지 판단
- 네 판단의 평균으로 위험선호 또는 위험회피 결정
- 기준선은 2023~2025년 실제 분포를 바탕으로 설정
- 이 기간 중 약 15%의 날이 위험회피로 판정됨
- 2023년 지역은행 사태, 2024년 엔캐리 청산, 2025년 관세 쇼크 구간이 위험회피로 잡힘

신호 통합 (동작함)

1. 세 관점 점수를 관점별 가중치로 가중합
2. 극단값이 튀지 않도록 -1 ~ +1 안으로 완만하게 압축
3. 절댓값 0.1 미만의 작은 신호는 0으로 처리해 잡음에 반응하지 않도록 함

관점 가중치 자동 조정 (동작함)

- 처음에는 세 관점을 1/3씩 반영
- 최근 60거래일 동안 예측이 잘 맞은 관점의 가중치를 높이고 틀린 관점은 낮춤
- 어떤 관점도 10% 밑으로는 내려가지 않음. 한 관점이 완전히 무시되지 않도록 하기 위함
- 어제까지 확정된 성적만 사용. 오늘 결과를 오늘 판단에 쓰면 미래를 보는 셈이기 때문
- 매일 처음부터 다시 계산하므로 백테스트를 중간부터 돌려도 처음부터 돌린 결과와 동일

### 2.6 주문 내기: 신호에서 비중, 주문까지 (일부)

- 판단 신호를 실제 목표 비중으로 바꾸는 단계
- 실행 순서가 고정되어 있음

처리 순서

1. 위험 한도 우선 적용
   - 종목별 변동성을 보고 상한을 정한 뒤 전략서 최대 비중과 비교해 작은 값을 사용
   - 결정을 내린 뒤 거부하는 방식이 아니라 한도를 넘는 결정이 애초에 나오지 않게 하는 방식
2. 신호를 비중으로 변환
   - 신호 -1이면 허용 범위 최저, +1이면 최고, 0이면 중간값
3. 합계 조정
   - 전체 합이 100%에서 최소 현금을 뺀 값이 되도록 비율 조정
   - 범위를 벗어난 종목은 범위 안으로 되돌림. 최대 3회 반복
4. 묶음 상한 적용 (두 겹, 순서 고정)
   - 먼저 자산군(주식, 채권, 원자재) 상한 적용. 성향별로 다름
   - 다음으로 국가(한국, 미국, 기타) 50%, 업종(반도체, 2차전지 등) 30% 상한 적용. 성향과 무관
   - 상한을 넘은 묶음은 그 안의 종목들을 같은 비율로 축소
5. 남은 금액은 현금으로 보관. 항상 최소 현금 이상이 됨
6. 주문 생성
   - 현재 비중과 목표 비중의 차이를 수량으로 환산
   - 너무 작은 차이는 무시

예시 (설계 문서의 검산 예제)

- 코스닥150은 신호가 가장 좋아 허용 범위 5~25% 중 상단인 21.2%까지 상승
- KODEX 200과 합친 국내주식 묶음이 52.6%로 상한 50%를 초과
- 두 종목을 같은 비율로 줄여 각각 29.8%, 20.2%로 조정
- 줄어든 2.6%는 현금으로 보관

현재 상태

- 비중 계산(2~5번)은 백테스트 안에서 동작함
- 실제 운용용 단계(위험 한도, 주문 생성, 가상 체결)는 아직 없음
- 11월 데모 범위는 가상 체결까지. 모의계좌 실주문은 12월 이후

### 2.7 백테스트: 과거 데이터로 돌려 보기 (일부)

- 전략이 과거에 어떤 성과를 냈을지 시뮬레이션

기간

- 2023-01 ~ 2025-12
- 첫 1년은 지표 준비 기간이고 성과는 2024-01부터 집계

리밸런싱 날짜마다 수행하는 일

1. 그날까지의 가격만 잘라 판단 단계에 전달
2. 판단 단계가 종목별 신호 산출. 지표 계산에 필요한 과거 이력이 부족한 종목은 중립 처리
3. 신호를 비중으로 변환 (2.6과 같은 계산)
4. 수수료와 슬리피지를 반영해 매매

결과 비교 대상

- 전략: 3관점 신호 사용
- 대조군: 같은 종목, 같은 제약, 신호 미사용
- 시장: KODEX 200 매수 후 보유
- 전략과 대조군의 차이가 곧 신호가 더한 가치

검증 방식

- 같은 계산을 파이썬과 타입스크립트 두 언어로 따로 구현
- 두 결과가 같은지 대조

현재 상태

- 스크립트로 직접 실행하면 동작함
- API로 요청하는 경로는 아직 없음
- 판단 점수가 아직 가짜라 현재 결과는 흐름 검증용이며 성과 판단용이 아님

### 2.8 결과 화면 (일부)

- 리포트 화면 (동작함): 백테스트 결과의 수익 곡선, 비중 변화, 지표 설명 표시
- 상태 화면 (동작함): 서버와 연결된 데이터베이스, 메시지 큐, 저장소, AI 서버 상태 표시
- 설문, 전략 만들기, 승인, 판단 근거 화면 (없음): 현재는 API 문서 화면(Swagger)에서 직접 호출해 사용

### 2.9 데이터 준비 (일부)

- 판단에 필요한 데이터는 모두 스크립트로 받아서 적재

데이터 종류

- ETF 종목 원장 (동작함)
  - 71종목
  - 자산군, 업종, 국가, 위험등급(G1 초고위험 ~ G6 초저위험), 레버리지 여부, 상장폐지 여부 포함
  - 위험등급과 분류는 사람이 검토
- 일별 가격 (동작함): 3년치 시가, 고가, 저가, 종가, 거래량
- 거시지표 (동작함): 변동성 지수, 환율, 신용 스프레드, 지수
- 전략 블록 사전 (동작함): 전략서에 들어갈 수 있는 값 목록. 블록 32개, 검색용 태그 91개
- 규칙표 (동작함): 성향과 위험등급 조합 30칸, 묶음 상한, 시스템 상한선
- 뉴스 (없음): 수집 기능이 제거되었고 저장 공간만 남아 있음

시점 이중 기록

- 가격은 거래일과 수집일을 함께 저장
- 거시지표는 기준일과 발표일을 함께 저장
- 거시지표는 늦게 발표되므로 판단 시 그날 이미 발표된 값만 쓰도록 하기 위함

규칙표 사본

- 규칙표 값은 데이터베이스, 백테스트, 화면 세 곳에 사본이 있음
- 값이 어긋나면 테스트가 감지

## 3. 사용자 한 명의 여정

1. 가입 후 출입증 수령
2. 설문 7문항에 답하고 성향 확정. 예: 위험중립형
3. "반도체랑 미국 주식 위주로, 매달 초에 정리해줘" 요청
4. 시스템이 작업 번호를 반환하고 뒤에서 처리 시작
5. AI가 문장에서 "반도체", "미국", "매달" 추출
6. 시스템이 위험중립형이 담을 수 있는 반도체, 미국 관련 종목을 선정하고 종목별 최대 비중 부여
   - 레버리지 종목을 지목했다면 "레버리지 금지" 이유와 함께 제외
7. AI가 후보 안에서, 정해진 범위 안에서 전략서 작성
8. 시스템이 관계 검사 후 초안으로 저장하고 완료 알림 전송
9. 이후 예정 단계: 검사 4단계, 백테스트 확인, 사용자 승인, 전략서 잠금
10. 이후 예정 단계: 리밸런싱 날마다 판단, 비중 계산, 주문, 가상 체결, 기록

## 4. 아직 비어 있는 곳

- 전략 검사
  - 없는 것: 4단 검사와 시스템 상한선 적용 본체
  - 영향: 상한선을 넘는 전략서도 저장됨
- 판단 모델
  - 없는 것: 시장분석 점수 모델, 감성 분석
  - 영향: 판단 점수가 가짜 또는 중립
- 실운용
  - 없는 것: 위험 한도, 주문 생성, 가상 체결, 매일 자동 판단
  - 영향: 백테스트 밖에서는 주문이 나가지 않음
- 화면
  - 없는 것: 설문, 전략, 승인, 판단 근거 화면
  - 영향: API 문서 화면에서 직접 호출해야 함
- 종목 원장
  - 없는 것: 저위험 주식형, 레버리지가 아닌 초고위험 종목
  - 영향: 안정투자형은 주식을 담을 수 없음. 성향 3, 4, 5가 고를 수 있는 종목이 동일함
